## Design Summary

Настроить окружение разработки в монорепо (Go backend + Next.js frontend) так, чтобы:

1. Тесты (`go test`, `pnpm test`) автоматически прогонялись перед завершением хода Claude — но экономно (один раз за ход, только по изменённым областям, без тяжёлого e2e).
2. Lint + formatter применялись на двух уровнях: точечно при правке файла Claude'ом (PostToolUse hook), и как страховка на всех staged-файлах перед git-коммитом (lefthook), независимо от инструмента редактирования.
3. Скилл `ui-ux-pro-max` гарантированно подключался при любой фронтенд-задаче через явное force-trigger правило в `frontend/AGENTS.md` — по той же схеме, что уже используется для Go-скиллов в корневом `AGENTS.md`.
4. Было объективно видно, какие skills/MCP реально сработали за сессию — через логирующий hook на вызовы `Skill`/`Task`, плюс короткая инструкция, как это проверить.

Сами хуки в `.claude/settings.json` пишутся не вручную, а через скилл `update-config`, чтобы формат конфигурации гарантированно был корректным.

## Alternatives Considered

### Alternative A: Только Claude Code hooks
- **Approach**: Вся автоматизация (тесты, lint/format, логирование) реализуется исключительно через hooks в `.claude/settings.json`, без git-хуков.
- **Pros**: Один конфигурационный файл, ничего не ставится в репозиторий (lefthook и т.п.), проще для старта.
- **Cons**: Не защищает от правок, сделанных вне Claude Code (руками, другим IDE, при мерже); нет страховки на уровне git-истории.
- **Why not chosen**: Пользователь работает не только через Claude Code — нужна защита, не завязанная на конкретный инструмент редактирования.

### Alternative B: Только git-хуки (lefthook everywhere)
- **Approach**: Вся проверка (тесты, lint, format) переносится в pre-commit/pre-push git-хуки через lefthook, без хуков Claude Code.
- **Pros**: Работает независимо от инструмента, стандартный подход для команд.
- **Cons**: Обратная связь приходит только в момент коммита, а не сразу при правке файла — медленнее итерация внутри сессии с Claude; git-хуки в принципе не видят вызовы skill/MCP внутри Claude Code, поэтому пункт 4 (видимость skills/MCP) нечем закрыть.
- **Why not chosen**: Теряется быстрая обратная связь во время активной работы с Claude и нет способа реализовать логирование skill/MCP-вызовов.

### Alternative C: Слоистый подход (выбран)
- **Approach**: Claude Code hooks для быстрой точечной обратной связи в процессе (lint/format на изменённый файл, тесты по изменённым областям раз в ход, лог skill/MCP-вызовов) + lefthook как repo-wide страховка на pre-commit, независимая от инструмента редактирования.
- **Pros**: Быстрая обратная связь там, где она нужнее всего (во время сессии с Claude), плюс независимая от инструмента страховка; решает все 4 вопроса пользователя без избыточной нагрузки (тесты и lint скоупятся по изменённым файлам/областям, а не гоняются целиком на каждый чих).
- **Cons**: Два места конфигурации (`.claude/settings.json` и `lefthook.yml`) вместо одного.
- **Why not chosen**: не отклонена — выбрана как основной подход.

## Agreed Approach

Alternative C (слоистый подход). Компоненты:

1. **Lint/format** — PostToolUse hook на `Edit`/`Write` точечно форматирует изменённый файл (`gofmt -w` для `.go`, `prettier --write` для frontend-файлов); lefthook на pre-commit проверяет все staged-файлы как страховку. Prettier + `prettier-plugin-tailwindcss` добавляются во frontend (сейчас есть только eslint).
2. **ui-ux-pro-max** — явное force-trigger правило в `frontend/AGENTS.md`, аналогичное существующему списку Go-скиллов в корневом `AGENTS.md`.
3. **Видимость skills/MCP** — PreToolUse hook на `Skill`/`Task` пишет строку (таймстамп, имя, входные данные) в `.claude/logs/skill-activity.log` (в `.gitignore`); в AGENTS.md — как это проверять (`tail -f` лога или разбор транскрипта).

Реализация hooks — через скилл `update-config`, а не ручное редактирование JSON.

## Key Decisions

- Формат/lint hook скоупится на изменённый файл, а не весь проект — дёшево и быстро.
- Для git-хуков выбран lefthook, а не husky — не тянет Node-специфичные зависимости, естественнее для смешанного Go+Node монорепо.
- Prettier + `prettier-plugin-tailwindcss` — новая зависимость frontend, которой сейчас нет (только eslint).
- Лог skill/MCP-активности — локальный файл, не отправляется никуда вовне; добавляется в `.gitignore`.
